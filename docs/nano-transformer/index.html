From First Principles

Nano Transformer

A LLaMA-style decoder inference engine from scratch in numpy — verified bit-exact

1The problem

Every production LLM serving stack (vLLM, TensorRT-LLM, llama.cpp) rests on a small set of inference primitives: normalized residual blocks, rotary position embeddings, grouped-query attention, gated FFNs, and incremental decoding against a KV cache. These are usually hidden inside framework kernels, so it is hard to verify what each piece computes, what it costs, and why the KV cache matters so much.

2The current gap

Most "build a transformer from scratch" material stops at a training loop for a toy model. It rarely (a) verifies each inference primitive against an independent reference implementation with assert-level tolerances, (b) proves that incremental cached decoding is numerically identical to a full forward pass, or (c) measures the actual latency and memory scaling of KV-cache vs recompute decoding on the same code.

3How the solution addresses it

src/llm_inference_engine/transformer/model.py implements the full inference path in ~350 lines of numpy with no ML framework:

  • TransformerConfig, RMSNorm, build_rope_cache / apply_rope (LLaMA-style halves pairing), repeat_kv for GQA, SwiGLU FFN.
  • KVCache: preallocated per-layer k/v buffers with append, advance, get, and an analytic bytes_for footprint helper.
  • TransformerModel.forward(tokens) (causally masked full pass), step(token, cache) (single-token incremental decode attending over the cached prefix), prefill, and generate (greedy or temperature/top-k).
  • experiments/run_experiments.py (seeded, np.random.default_rng(7)): four assert-level numerical verifications, latency benchmarks (median of 15 reps via time.perf_counter), analytic KV-memory accounting, and chart + markdown report generation into results/.

6Insights

  • The KV cache is the whole game for decode. Cached decode stays nearly flat (~1-5 ms/token) while full-context recompute grows steeply with sequence length (~21 ms at 32 tokens, ~646 ms at 512) — a 137x gap at seq 512 on identical hardware and code. Prefill is the price of admission; decode is where the cache pays off.
  • Exactness is achievable, not approximate. Cached incremental decode reproduces full-forward logits bit-for-bit (max diff 0.0), because each cached key is rotated by RoPE at its own absolute position and attention is evaluated over the identical prefix in the identical order. There is no mathematical reason for "close enough" here.
  • GQA is pure bookkeeping. With tied weights, grouped-query attention is bit-identical to full multi-head attention (diff 0.0) — repeating KV heads is a memory/compute tradeoff, not an approximation.
  • KV memory is linear and plannable. 256 KiB at seq 512 for this nano config (fp16); the formula has no surprises, which is exactly why serving systems can budget it per request.
  • Benchmark on a quiet machine if you want tight numbers. Medians over 15 reps still jittered ~2x run-to-run on a shared 2-core VM; the scaling shapes and orders of magnitude were stable, the last digits were not.
