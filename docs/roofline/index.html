From First Principles

Roofline Analysis

Per-op roofline model for inference: where the wall is, and what fusion moves

1The problem

LLM serving has two latency regimes with opposite bottlenecks. Decode (one token at a time) feels slow because each step re-reads the entire weight matrix for a handful of FLOPs; prefill (the prompt pass) is a different animal. Without a quantitative model, "make it faster" devolves into guessing which kernel to optimize.

2The current gap

Most roofline treatments of transformers stop at a single GEMM or quote aggregate TFLOPS. This project builds a per-op roofline for a full decoder layer — QKV projection, QK^T, softmax, AV, output projection, SwiGLU FFN — with explicit byte accounting (weights, activations, KV-cache reads), so each op gets an arithmetic intensity, a bound label, a % of peak, and an estimated time. Fusion is modeled as a transform on the byte traffic, not hand-waving.

3How the solution addresses it

src/llm_inference_engine/roofline/ (numpy, CPU-only, analytical):

  • hardware.py — Hardware dataclass (peak FLOPS per dtype, memory bandwidth). A100 (312 dense FP16 TFLOPS, 2039 GB/s), H100 (989 dense FP16 TFLOPS, 3350 GB/s) from published specs; an illustrative CPU reference.
  • ops.py — FLOP/byte accounting per op for a layer config (d_model, n_heads, ffn_mult, batch, seq, dtype). Decode reads the KV cache for one query token; prefill materializes the SxS score matrix.
  • model.py — roofline classification (attainable = min(peak, intensity * bw), % of peak, memory/compute-bound vs the ridge point) plus two fusion transforms: - FlashAttention-style: QK^T + softmax + AV fused; the score matrix is never materialized, so bytes drop from O(BHS^2) to O(BHS). - Fused dequant+GEMM: weights stored quantized (e.g. INT8) and dequantized on the fly; weight-read bytes scale by the byte ratio.

experiments/run_experiments.py is deterministic (analytical; two runs produce identical SHA-256 fingerprints of the outputs).

6Insights

  • Decode is memory-bound — bandwidth is the wall. At ~1 FLOP/byte against a 153 FLOP/byte ridge point, no amount of extra FLOPS helps; only less traffic (quantized weights, larger batches) or more bandwidth does.
  • Prefill is compute-bound for the projections but the attention ops stay memory-bound because of the materialized SxS matrix — which is exactly what FlashAttention removes.
  • Fusion moves the ceiling, not the wall: FlashAttention shifts attention from the bandwidth ceiling to the compute ceiling (big win in prefill, ~nothing in decode), while weight quantization raises effective intensity against the unchanged bandwidth wall (the real lever for decode latency: 1.83x estimated step speedup).
